# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project north star (read this first)

The **single goal** of this project is: **reduce the number of visual tokens sent to the generation model after multimodal retrieval**, ideally without hurting answer quality or net latency. Every change should be judged against that goal.

A detailed critique of how the project currently fails to *measure* and *serve* that goal lives in [REFLECTION_REVIEW_zh.md](REFLECTION_REVIEW_zh.md), and the agreed improvement plan is [thoughts/plans/2026-06-17-clip-safecrop-and-token-measurement.md](thoughts/plans/2026-06-17-clip-safecrop-and-token-measurement.md). Before proposing pruning/eval changes, read both — they encode decisions already made with the user.

**Known traps the reflection identified (do not repeat these):**

1. **The pruning "signal model" is NOT the "answer model."** Cropping decisions come from a separate **Qwen2-VL-7B** (`rag/qwen2vl_catp_pruner_v2.py`), but answers are generated by **Qwen3-Omni-30B** via vLLM (`rag/config.py`). `tokens_before/tokens_after` are counted on the 7B's grid, **not** on what the 30B actually consumes — so reported reductions are not the real metric. Real token counts must use the *target* model's image processor.
2. **The main-goal metric is not aggregated.** `aggregate_summary` in `rag/metrics.py` reports latency + accuracy only; visual-token reduction is computed per-image but never averaged or plotted. A change that claims to reduce tokens must surface an aggregate token-reduction number.
3. **Pruning-on-the-fly can be a net loss.** The 7B forward uses `eager` attention + `output_attentions` + `output_hidden_states` (most expensive mode), so on-the-fly pruning is *slower* than no pruning, and accuracy drops ~10%. Favor cheaper signals (CLIP) and/or moving pruning off the critical path.
4. **Spatial layout matters.** The downstream visual encoder relies on positional relationships. `safecrop` (single bounding box) preserves layout; the `montage` path (`visual_patch_pruning`) and multi-subimage `cluster` path do not. Per user decision, **do not stitch/rearrange crops**.

## Environment & data setup

```bash
conda env create -f environment.yml   # creates env "mrag"
conda activate mrag
bash scripts/download_mmdocrag.sh      # downloads annotations + images.zip into data/mmdocrag/
```

`data/` is gitignored. Dataset annotations are JSONL (one example per line); `rag/mmdocrag_dataset.py` normalizes each row and maps the answer from the `answer_short` field. Image paths in the dataset are relative and joined to `images_root`.

## Running (two terminals)

The benchmark is an **OpenAI-compatible client**; it needs a vLLM server already running.

**Terminal 1 — serve the VLM** (optionally with LMCache; point `LMCACHE_CONFIG_FILE` at `config.yaml` and align its `local_disk` path with `RAGConfig.lmcache_path`):
```bash
PYTHONPATH=$PYTHONPATH:. python -m vllm.entrypoints.openai.api_server \
  --model Qwen/Qwen3-Omni-30B-A3B-Instruct --max-model-len 16384 \
  --gpu_memory_utilization=0.5 --host 0.0.0.0 --port 8000
```

**Terminal 2 — run the benchmark** (note: the actual script is `run_mmdocrag_benchmark.py`; the README spells it `run_mmodcrag_benchmark.py` by mistake):
```bash
# Eval JSONL lines [0,50), no row cap (--max-examples 0 means "no cap")
PYTHONPATH=$PYTHONPATH:. python scripts/run_mmdocrag_benchmark.py \
  --eval-slice-start 0 --eval-slice-stop 50 --max-examples 0
```
Flags: `--eval-slice-start I` / `--eval-slice-stop J` select a JSONL line window `[I, J)`; `--max-examples N` caps rows after slicing (`0` = no cap). All other knobs (pruning mode, keep ratio, model names, top-k, cache threshold) live in `rag/config.py:RAGConfig` and are edited there, not via CLI.

There is **no lint config and no test suite** in the repo today. To smoke-test code changes without a GPU/server, import-check modules: `PYTHONPATH=. python -c "import rag.eval"`.

## Architecture: the request lifecycle

The whole pipeline is orchestrated per example in `RAGPipeline.run_one` (`rag/query_pipeline.py`):

1. **Retrieve** (`rag/retriever.py:QuoteRetriever`): text→text via SentenceTransformers; text→image via CLIP. Selected image quotes carry a query-conditioned CLIP `tag` vector used later for caching. (`rag/retriever_CoarseImgCondSemantic.py` is an alternate retriever variant with a different `tag` formula — not wired into the default pipeline.)
2. **Disk-cache lookup** (`_split_cached_images`): for each retrieved image, if a previously pruned version exists for the *same* `image_cache_id` and the query `tag` cosine-similarity exceeds `image_prune_cache_similarity_threshold`, reuse the stored pruned image and skip pruning. Cache index is `image_prune_cache.json`.
3. **Prune** (`rag/pruner.py:RetrievalPruner.apply`): dispatches on `pruning_mode`. This is where the project's goal is implemented. See modes below.
4. **Build prompt** (`rag/prompt_builder.py`): assembles text + image-evidence blocks. For cluster outputs it loads per-cluster `annotation` JSONs and lists them; switches to a terse VQA prompt when there's exactly one image and no text.
5. **Generate**: streams from the vLLM chat endpoint, measuring TTFT and generation time. **Image encoding branches on the path**: a `.jpg` path → one `image_url`; a *directory* path → one `image_url` per sub-image jpg inside it.
6. **Store to cache** (`_store_pruned_images_in_cache`) and return timings + per-image pruning metadata.

**Crucial side effect:** the pruner **overwrites** `q["local_img_path"]` to point at the pruned artifact. Any code needing the original image (e.g. counting "tokens before") must capture the path *before* `pruner.apply()` runs.

### Pruning modes (`RetrievalPruner`)

- `no_pruning` — passthrough.
- `visual_patch_pruning` — CLIP scores a `patch_grid_rows × patch_grid_cols` tile grid vs the query, keeps top tiles, then **montages** them onto a new canvas (breaks spatial layout). Loads its own CLIP.
- `safecrop_pruning` / `cluster_pruning` — use the **7B Qwen2-VL** proxy (`Qwen2VLCATPBoundingBoxCropper.get_pruned_image`): fuse query→image attention over layers 10–13, diversity-filter patches, then either one bounding box (`_safe_crop`, layout-preserving, → single jpg) or multiple boxes (`_cluster_crop`, → a directory of sub-image jpgs + cluster JSONs). `IS_TOPK` and `keep_ratio`/`percentile_ratio` control selection; there are several fallbacks (e.g. "Sparse Patch Problem" → revert to full image).

The output **format** (single jpg vs directory of jpgs) is what determines how many `image_url`s the pipeline sends — this directly couples pruning mode to token count and is easy to get wrong (N small sub-images can cost *more* tokens than one downscaled image).

### Evaluation

`rag/eval.py` runs two passes: `run_rag_benchmark` (online serving + lexical/retrieval metrics → `baseline_predictions.json`) then `run_rag_benchmark_offline_judge` (LLM-as-judge correctness/score → `baseline_results_judged.json`). The `scripts/run_mmdocrag_benchmark.py` wrapper additionally scrapes vLLM/LMCache Prometheus metrics (`rag/vllm_metrics.py`) and host memory before/after, writing `final_results_with_utilization.json`. `rag/metrics.py:aggregate_summary` is the single place where run-level averages are computed.

## Outputs (under `data/mmdocrag/outputs/` by default)

`baseline_predictions.json` (online), `baseline_results_judged.json` (+ judge fields, + appended `lmcache` block), `image_prune_cache.json` (reuse index), `pruned_images/` (pruned artifacts), `final_results_with_utilization.json` (summary + utilization). Result figures are checked into `imgs/`.

## Conventions

- Run everything from repo root with `PYTHONPATH=.`; the `rag` package uses absolute imports (`from rag....`).
- All tunable behavior is centralized in `rag/config.py:RAGConfig`; prefer adding a field there over hardcoding.
- Tested on NVIDIA H200; the 7B pruner caps effective pixels (`_DEFAULT_CATP_MAX_PIXELS`, overridable via `MRAG_CATP_MAX_PIXELS`) to avoid OOM from full attention/hidden-state capture.
